**AC를 받은 코드도 틀릴 수 있다.** 채점 데이터가 약하면 버그가 통과한다. `/review`에서 코드 정확성은 "AC였다"를 근거로 넘기지 말고, 의심되면 실측으로 검증할 것.

## ★ 백준 10025 게으른 백곰 — 발행 보류 (2026-07-18)

3차 배치에서 **제외**됨. `_drafts/` 루트로 뺐고(발행 안 함), Algorithm 레포는 원본 6파일로 복구(`git checkout HEAD`)돼 깨끗함. 포스트에 3접근 6블록 중 **4개가 AC인데 오답**:

- **투 포인터 (Main3)**: `input[r]-input[l] > (2*k+1)` 조건이 off-by-one. 두 양동이가 동시에 닿을 최대 거리는 **2K**인데(`[p-K,p+K]` 폭), `2K+1`은 *칸 수*지 *거리*가 아님. 거리 정확히 2K+1인 쌍을 잘못 받음. 브루트포스 대조 752/3000 불일치. `> 2*k`가 정답.
- **누적 합 (Main)**: `psum[i+size]-psum[i]`가 좌표 `i+1..i+size` 구간이라 **좌표 0에서 시작하는 윈도우를 못 봄**. 274/3000 불일치. **좌표 0에 양동이가 있을 때만** 발동(백만분의 1이라 실전 분포에선 거의 안 터짐).
- **슬라이딩 윈도우 2개만 정상** (초기 윈도우를 `arr[0..sz-1]`로 잡아 좌표 0 커버).
- **예제 입력은 4개 다 11로 통과** → 예제로는 버그가 안 드러남. BOJ 데이터가 약했던 것.

**사용자 결정: 코드 수정 안 함.** BOJ 2026-04-28 종료로 재채점 불가라 확신 못 하겠다는 이유([[boj-shutdown-status]]). **다음 세션이 10025를 다시 만져도 이 결론을 재검증하지 말 것** — 보류는 사용자의 명시적 선택. 고칠 거면 Algorithm 레포 원본(Main=누적합, Main3=투포인터) 고친 뒤 `/sync`. solved.ac 태그는 수학/구현/누적 합(sliding window 아님, 확인됨).

## ★ 검증 방법론 (재사용 가능)

1. **같은 포스트의 여러 풀이가 서로 다른 답을 내면 최소 하나는 틀림.** 이게 *내 문제 해석과 무관한* 결정적 증거다. 사용자가 "문제 조건을 잘못 안 것 아니냐"고 밀어붙일 때, 문제 해석 논쟁을 우회하는 최선책. 10025는 슬라이딩(9)과 투포인터(14)가 갈렸음 → 해석 무관하게 하나는 오답.
2. **반례는 반드시 컴파일 + 브루트포스 대조로 실측.** 손 추론 반례는 신뢰하지 않는다. 브루트포스는 문제 정의 그대로(모든 후보 완전 탐색). macOS clang은 `#include <bits/stdc++.h>` 없음 → 필요한 헤더로 교체하되 로직 불변, `-std=c++17`(structured binding).
3. **제약을 원문에서 직접 확인**하고 위반 입력으로 반례 만들지 말 것. 처음에 K=0(제약은 1≤K)을 섞어 헛다리 짚었음. 원문은 iCloud 미러([[boj-shutdown-status]]).
4. **버그 발동 조건이 좁으면(경계 케이스) AC가 자연스럽다** — "AC인데 왜 틀리냐"의 답. 데이터 제작자가 흔히 빠뜨리는 자리(왼쪽 끝단, 경계+1)에 버그가 겹치면 구조적으로 안 걸린다.
5. **서브에이전트도 코드 정확성을 오판한다.** 이 세션에서 Sonnet 리뷰 에이전트가 10025 누적합을 "정확"으로 판정했으나 실측 오답. 백지 검증(Opus, 힌트 없이)은 8/8 잡아냈지만 "수정 불필요"가 하나도 안 나온 편향도 감안할 것.

## 제약이 아슬아슬하게 막아주는 사례 (오탐 주의 — 전부 정상)
같은 배치에서 "오버플로/경계 위험해 보이는데?"가 3건 나왔으나 제약이 막고 있어 정상이었음:
- **2473 세 용액**: `sum` 초기값 3e9 = 세 값 합 절댓값 최댓값과 동일. 하지만 "특성값 모두 다르다"라 실제 최댓값 2,999,999,997 < 3e9. 안전.
- **27436 벌집 2**: `mid` 상한 2e9면 `3*mid*(mid-1)`이 long 초과. 하지만 N≤9e18에서 실제 탐색 max mid=1.75e9 → 0.39% 여유로 통과.
- **17128**: `sum`이 int인데 |S| 최대 2e9 < int_max 2.147e9. 7% 여유.
→ **"위험해 보인다"로 지적하기 전에 제약 상한을 넣어 실제 도달 값을 계산할 것.**
